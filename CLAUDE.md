## Naming (do not confuse these)
- **Source side** (`gldwrs2`): GitHub repo, Go module path, local project directory. Never appears on the command line.
- **User side** (`gw2`): binary, Cobra root command, Homebrew cask, npm package (`@howar31/gw2`), generated skills, config dir, `GW2_*` env vars.

## Run / build
```bash
go build -o gw2 ./cmd/gw2                   # version comes from the committed VERSION file
go test ./...                               # includes the command-coverage meta-test
go run ./cmd/gw2 generate-skills            # regenerate skills/ after any command change
scripts/smoke.sh                            # live smoke vs the real API (authed part needs a stored profile)
goreleaser check                            # validate .goreleaser.yaml (no network/publish)
goreleaser release --snapshot --clean       # local dry-run only, never plain `release`
```

## Conventions
- Code comments in English (repo-wide rule). Docs: SPEC.md / CLAUDE.md in English; README.md is human-facing.
- One file per command group under `internal/commands/`, paired `_test.go`; every leaf command must be exercised via `markCovered` — `zz_coverage_test.go` fails otherwise. Never filter `go test -run` to exclude `TestZZ...`.
- Shared leaf shapes: `newByIDsListCmd`/`newSimpleGetRunE` (`leaf.go`) for the enumerate/by-ids and plain-GET patterns; `addToTree` (`tree.go`) for nested command-group registration from a flat resource table.
- Authenticated leaves use `app.authedClient()` (errors up front if no key configured); public leaves use `app.client()` (anonymous is fine).
- `VERSION` is the version SSOT (embedded via `go:embed` in `version.go`). Keep `npm/package.json`'s `version` and any future release tooling in sync with it.
- Regenerate `skills/` (`gw2 generate-skills`) after adding/removing a command or changing flags — output is deterministic, so drift is mechanically detectable.
- Read-only API: no `--dry-run`/write-CAUTION machinery exists or is needed — every command is a GET.

## Distribution guardrails
- `.goreleaser.yaml` pins `release.github: {owner: howar31, name: gldwrs2}` explicitly (repo name differs from the `gw2` binary/cask name, and goreleaser can't infer it without a configured git remote).
- Do not run `goreleaser release` (without `--snapshot`) or `npm publish` from a local session; those are release-time actions requiring explicit user approval.

## Privacy
Never write any AI-persona/assistant-identity name or private-roster/employer label into any committed file. Refer to consuming agents generically (e.g. "an AI coding agent such as Claude Code").
